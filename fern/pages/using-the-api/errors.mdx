## Error object shape

The Stripe specs list the Error object as one of their key concepts. The recommended GA spec, `latest/openapi.spec3.json`, describes 703 operations, and failures from those operations are described by this object.

The schema definitions live under `components` in the spec file, the same place as the `securitySchemes` definitions.

To see the exact properties, open `latest/openapi.spec3.json` and find the error schema in `components`. The names of its properties, and which of them are required, (needs confirmation) from the spec.

## Handling errors in generated clients

Both security schemes in the spec, `basicAuth` and `bearerAuth`, use Stripe API keys against `https://api.stripe.com/`. A request that fails because of a missing or wrong key is therefore one of the failures your client has to handle.

How a generated client exposes error responses, for example as typed exceptions or as result objects, depends on the generator you use. The spec does not define this (needs confirmation). For generator-specific caveats, see [Generating SDKs and clients](/building-tools/generating-sdks).
