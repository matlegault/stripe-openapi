Stripe's specs use x- vendor extensions to carry information that is hard to express in plain OpenAPI, and this page explains how to read each one.

The README says the specification ships "a few vendor-specific fields" for this purpose.

## x-resourceId and fixtures

Resources include `x-resourceId`, a canonical name for each resource.

You can use it with `openapi/fixtures{2,3}.{json,yaml}` to look up a sample representation of the resource, known as a "fixture".

The README's example shows a `charge` definition with `x-resourceId: charge`, and a separate fixtures file keyed by resource name.

```yaml
# spec.yaml
---
definitions:
  ...
  charge:
    ...
    x-resourceId: charge

# fixtures.yaml
---
invoice_line_item:
  ...
```

For a task-oriented walkthrough, see [Working with fixtures](/spec-conventions/fixtures). (needs confirmation)

## x-expandableFields

A resource's `x-expandableFields` lists the fields that can be expanded by making an API request with an `expand` parameter.

```yaml
definitions:
  ...
  charge:
    ...
    x-expandableFields:
    - balance_transaction
```

In this example from the README, `balance_transaction` is expandable on `charge`.

## x-expansionResources

Each expandable field within a resource carries `x-expansionResources`, a set of references to the resources the field might be expanded to.

```yaml
definitions:
  ...
  charge:
    properties:
      ...
      balance_transaction:
        description: ID of the balance transaction that describes the impact of this
          charge on your account balance (not including refunds or disputes).
        type:
        - string
        x-expansionResources:
          oneOf:
          - "$ref": "#/definitions/balance_transaction"
```

Here the field is a string ID by default, and `x-expansionResources` points to the `balance_transaction` resource it expands to.

See [Expanding related objects](/spec-conventions/expanding-objects) for how the two expansion extensions work together. (needs confirmation)
