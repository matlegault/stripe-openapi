This page lists every spec file in the Stripe OpenAPI repository with its directory, variant, format and operation count.

The repository publishes specs in three directories: `latest/`, `preview/` and `openapi/`. Each spec comes in JSON and YAML.

## latest/

`latest/` holds the latest generally available (GA) release. It is the recommended directory and covers both v1 and v2 API endpoints and events in a single file.

Use these files to generate SDKs or client libraries for Stripe's API.

| File | Variant | Operations |
|------|---------|------------|
| `latest/openapi.spec3.json` | Public | 703 |
| `latest/openapi.spec3.sdk.json` | SDK | 650 |

## preview/

`preview/` holds the latest public preview release. It is the same as `latest/`, but it includes public preview API endpoints. Use it for early access to upcoming API features before GA.

| `preview/openapi.spec3.sdk.json` | SDK | 803 |

## openapi/ (legacy)

`openapi/` holds the original files, which contain v1 endpoints only. They are still updated with every release. New projects should use `latest/` for complete API coverage. If you already use `openapi/`, you don't need to change anything.

The README also says that `openapi/` contains the fixtures files, named `fixtures{2,3}.{json,yaml}`, which pair with `x-resourceId` to look up sample resource representations.

## Format pairs

Every specification file is available in both JSON and YAML.

Two variants exist, distinguished by file name:

- **Public specs** use the `spec3.{json,yaml}` name. Use these for most purposes.
- **SDK specs** use the `spec3.sdk.{json,yaml}` name. They contain special annotations, deprecated endpoints and pre-release features meant to support generating Stripe API libraries. Use the public variant unless you are generating a library.

The JSON files in this page's sources have YAML counterparts with the same base name and a `.yaml` extension.

To decide which file fits your task, see [Choosing the right spec file](/concepts/choosing-a-spec). (needs confirmation)
