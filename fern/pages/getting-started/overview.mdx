This page explains what the Stripe OpenAPI repository publishes, who the specs are for, and how the latest, preview and legacy directories differ.

## What this repository is

The repository contains OpenAPI specifications for Stripe's API.

The specs are generated by a custom closed-source generator. They do not explicitly target openapi-generator.

OpenAPI 2.0 is deprecated and no longer receives updates. It remains available on old versions of the repository.

The main spec, `latest/openapi.spec3.json`, describes 703 operations.

Both security schemes use Stripe API keys, and they are declared at the top level of the spec. The scheme definitions live under `components/securitySchemes`.

## Who it is for

Use these specs if you generate SDKs or client libraries for Stripe's API. The `/latest/` files are intended for that purpose.

You can also use them to build tooling or to integrate with the Stripe API through OpenAPI-based tools. Most users should pick the public spec variant.

## Repository layout

The repository has three spec directories.

| Directory | Description |
|-----------|-------------|
| `/latest/` | Recommended. Latest GA release with v1 and v2 API endpoints. |
| `/preview/` | Same as `/latest/`, but includes public preview API endpoints. |
| `/openapi/` | Legacy. v1-only endpoint specifications, still updated every release. |



## GA, preview and legacy specs

- **`/latest/`** holds the latest generally available release. It includes v1 and v2 endpoints and events, so one file gives complete API coverage.
- **`/preview/`** holds the latest public preview release. Use it for early access to upcoming API features before they reach GA.
- **`/openapi/`** holds the original v1-only files. They are still updated with every release, and the existing structure is unchanged. New projects should use `/latest/` instead.

## JSON and YAML formats

Every specification file is available in both JSON and YAML.

Each directory offers two variants:

- **Public specs** (`spec3.{json,yaml}`) suit most purposes.
- **SDK specs** (`spec3.sdk.{json,yaml}`) contain special annotations, deprecated endpoints and pre-release features. They exist to support generating Stripe API libraries, and you should typically use the public variant instead.
